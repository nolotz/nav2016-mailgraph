# Patch: Page 409 "SMTP Mail Setup" (NAV 2016)

Adds a **Microsoft Graph** group with the new Table 409 fields, a masked client-secret field that writes
into Table 1261 "Service Password" via Codeunit 50400, a test-recipient field, and two actions:
**Test Graph Connection** and **Send Graph Test Email**. The standard action **Test Email Setup**
(Codeunit 412 "SMTP Test Mail") is enabled when Graph is the transport.

> This file does not contain the Microsoft object. Apply the change to the Page 409 of your own database.
> Prerequisites: [TAB409.md](TAB409.md) applied and Codeunit 50400 imported (the page references both).

What is known about the standard NAV 2016 Page 409 (Version List `NAVW18.00`): the Password field is
`ExtendedDatatype=Masked; SourceExpr=Password; Editable=PasswordEditable`, a Boolean `CanSendTestMail`
(`"SMTP Server" <> ''`) enables the action *Test Email Setup* (`CODEUNIT.RUN(CODEUNIT::"SMTP Test Mail")`),
and the action *Apply Office 365 Server Settings* calls `SMTPMail.ApplyOffice365Smtp(Rec)`
(source: [research-notes](../../docs/research-notes.md), "Dynamics NAV 2016 internals"). The exact
trigger in which `CanSendTestMail` is computed is **not** reproduced here – search for it in your object.

## Steps (C/SIDE Page Designer)

1. Object Designer → Page 409 → **Design**.
2. **Globals** (View → C/AL Globals → Variables), add:

   | Name                | DataType  | Subtype | Notes |
   |---------------------|-----------|---------|-------|
   | GraphMail           | Codeunit  | 50400   | "Graph Mail" |
   | GraphClientSecret   | Text      |         | no length |
   | GraphTestRecipient  | Text      |         | no length |
   | GraphSecretEditable | Boolean   |         | |
   | GraphCertEditable   | Boolean   |         | |

3. **Functions** tab, add a local function `UpdateGraphControls` (no parameters, Local = Yes) with the code
   from the snippet below.
4. Find the place where `CanSendTestMail` is assigned (C/AL editor, search `CanSendTestMail :=`) and change
   the assignment to

   ```
   CanSendTestMail := ("SMTP Server" <> '') OR ("Mail Transport" = "Mail Transport"::"Microsoft Graph");
   ```

   and add a call to `UpdateGraphControls;` directly after it. If the page has no `OnAfterGetRecord`
   trigger that runs this code for every record, also add `UpdateGraphControls;` to `OnAfterGetRecord`.
5. Add the controls: below the last existing group of the ContentArea add a new line
   Type `Group`, SubType `Group`, Caption "Microsoft Graph" (CaptionML ENU/DEU), Indentation 1, and below it
   (Indentation 2) the fields from the snippet: `"Mail Transport"`, `"Graph Tenant ID"`, `"Graph Client ID"`,
   `"Graph Auth Method"`, `GraphClientSecret` (page variable), `"Graph Cert. Thumbprint"`,
   `"Graph Sender Mailbox"`, `"Graph Reply-To Caller"`, `"Graph Save to Sent Items"`, `"Graph Large Messages"`,
   `"Graph Token Library"`, `"Graph Cloud"`, `"Graph Log File Path"`, `GraphTestRecipient` (page variable).
   Set the properties (CaptionML, ExtendedDatatype, Editable, OnValidate) as in the snippet.
   Do **not** add field `"Graph Secret Key"`.
6. **Actions** (View → Page Actions): in the existing ActionItems container add the two actions from the
   snippet next to *Test Email Setup*.
7. Update the Version List (append `,NMG1.00`), save, compile.

`CurrPage.SAVERECORD` writes pending changes of the setup record first, because Codeunit 50400 reads
Table 409 from the database. No `Image=` property is given because the image names were not verified for
NAV 2016; pick one in the designer if you like.

### Globals and function (CODE section)

```
    VAR
      GraphMail@50100 : Codeunit 50400;
      GraphClientSecret@50101 : Text;
      GraphTestRecipient@50102 : Text;
      GraphSecretEditable@50103 : Boolean INDATASET;
      GraphCertEditable@50104 : Boolean INDATASET;

    LOCAL PROCEDURE UpdateGraphControls@50100();
    BEGIN
      GraphSecretEditable := "Graph Auth Method" = "Graph Auth Method"::"Client Secret";
      GraphCertEditable := "Graph Auth Method" = "Graph Auth Method"::Certificate;
      // Never load the real secret into the page; show a placeholder when one is stored.
      IF GraphMail.HasClientSecret(Rec) THEN
        GraphClientSecret := '**********'
      ELSE
        GraphClientSecret := '';
    END;
```

`INDATASET` is how the designer exports the variable property *IncludeInDataset = Yes*, which is what
Microsoft uses for Boolean variables bound to `Editable`/`Visible`. If you create the variables in the
designer, set **IncludeInDataset = Yes** on the two Booleans.

## Behaviour

* **Client Secret field**: entering a value stores it via `GraphMail.SetClientSecret(Rec, …)` in Table 1261
  (encrypted when the database has an encryption key; otherwise Codeunit 50400 shows a warning). Clearing the
  field deletes the stored secret. The page only ever shows the placeholder `**********`, never the secret.
  The setup record itself (field "Graph Secret Key") is saved by the page like any other field change; if your
  Page 409 variant does not save automatically, add `CurrPage.SAVERECORD;` after `SetClientSecret`.
* **Test Graph Connection**: acquires a token with the current settings (works while *Mail Transport* is still
  SMTP) and shows success or the full error text including hints from the add-in.
* **Send Graph Test Email**: sends an HTML test mail to *Test E-Mail Recipient* through Graph, independent of
  *Mail Transport*. Without a *Graph Sender Mailbox* the recipient is also used as sender.
* **Test Email Setup** (standard, Codeunit 412): goes through Codeunit 400 and therefore through Graph when
  *Mail Transport* = Microsoft Graph. Its body still lists the SMTP fields – that is expected.
* The SMTP fields stay on the page; they are ignored while *Mail Transport* = Microsoft Graph. Switching back to
  SMTP is the rollback.
