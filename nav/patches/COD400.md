# Patch: Codeunit 400 "SMTP Mail" (NAV 2016)

Makes Codeunit 400 delegate to Codeunit 50400 "Graph Mail" when Table 409 *Mail Transport* = Microsoft Graph.
**All Codeunit 400 signatures stay unchanged**, so no caller (Codeunit 9520 "Mail Management", 412 "SMTP Test
Mail", 260 "Document-Mailing" via 9520, reminders, report mailing, customer code) has to change.

> This file does not contain the Microsoft object. Only signature lines (from
> [research-notes](../../docs/research-notes.md), NAV 2016 CU1 build 43402) are shown to locate the insertion
> points; parameter IDs (`@1000`…) are omitted because they may differ in your build. `…` stands for the
> unchanged original code. Compare against **your** Codeunit 400 first – partners often modified it
> (use [../tools/Find-SmtpCallers.ps1](../tools/Find-SmtpCallers.ps1) to find other objects that use it).

Prerequisites: [TAB409.md](TAB409.md) applied, Codeunit 50400 imported.

## Principle

* Every delegation is inserted as the **first statements** of the function body, before any original line.
  The original SMTP code stays untouched below, so the diff is small and rollback is just "Mail Transport = SMTP".
* `UseGraph` is decided once per message in `CreateMessage` and kept for the life of the Codeunit 400 instance,
  so `TrySend` and the following `GetLastSendMailErrorText` (Codeunit 9520 pattern) stay on the same transport.
* In `CreateMessage` the Graph check comes **before** `SMTPMailSetup.TESTFIELD("SMTP Server")` (it is the very
  first statement), so a Graph-only setup with a blank *SMTP Server* works.
* Codeunit 50400 repeats the address validation of Codeunit 400 (via Codeunit 9520 `CheckValidEmailAddresses`),
  the attachment `EXISTS` check, the Codeunit 419 file-name cleanup and the `TrySend`/`Send` error contract.

## 1. Globals

Add two global variables (View → C/AL Globals). IDs 50100/50101 avoid collisions with Microsoft's 1000+ range.

```
      GraphMail@50100 : Codeunit 50400;
      UseGraph@50101 : Boolean;
```

## 2. Functions – before / after

### CreateMessage

Before:
```
    PROCEDURE CreateMessage@1(SenderName : Text;SenderAddress : Text;Recipients : Text;Subject : Text;Body : Text;HtmlFormatted : Boolean);
    BEGIN
      …   // address checks, SMTPMailSetup.GET; SMTPMailSetup.TESTFIELD("SMTP Server"); Mail := Mail.SmtpMessage; …
    END;
```
After:
```
    PROCEDURE CreateMessage@1(SenderName : Text;SenderAddress : Text;Recipients : Text;Subject : Text;Body : Text;HtmlFormatted : Boolean);
    BEGIN
      UseGraph := GraphMail.IsEnabled;
      IF UseGraph THEN BEGIN
        GraphMail.CreateMessage(SenderName,SenderAddress,Recipients,Subject,Body,HtmlFormatted);
        EXIT;
      END;
      …   // original code unchanged (incl. TESTFIELD("SMTP Server"))
    END;
```

### TrySend

Before:
```
    PROCEDURE TrySend@10() : Boolean;
    BEGIN
      …   // SendResult := Mail.Send(...); Mail.Dispose; CLEAR(Mail); EXIT(SendResult = '');
    END;
```
After:
```
    PROCEDURE TrySend@10() : Boolean;
    BEGIN
      IF UseGraph THEN
        EXIT(GraphMail.TrySend);
      …
    END;
```
`GraphMail.TrySend` never raises an error (configuration errors become the error text), exactly like the
original, which returns `SendResult = ''`.

### IsEnabled

`IsSMTPEnabled`/`IsEnabled` and Codeunit 1509 "Notification Entry Dispatcher" depend on it.

Before:

### HandleSMTPRegisterServiceConnection (event subscriber)

`[EventSubscriber(Table,1400,OnRegisterServiceConnection)] HandleSMTPRegisterServiceConnection@14` registers
the SMTP setup on the *Service Connections* page and reports it as **Disabled** when *SMTP Server* is blank.
Keep the subscriber attribute and signature unchanged. In its body, find the condition that decides
"Disabled" from `"SMTP Server" = ''` and extend it so Graph counts as enabled:

```
      // original condition:          … "SMTP Server" = '' …
      // change it to:                … ("SMTP Server" = '') AND NOT GraphMail.IsEnabled …
```

The exact statement is not reproduced here (Microsoft code); the change is one condition. If the
subscriber uses a local Record 409 inside a `WITH … DO`, `GraphMail` still resolves to the global variable
(Table 409 has no member with that name).

## 4. Other objects that look at SMTP directly (NAV 2016 W1 CU1)

In the unmodified NAV 2016 CU1 export only these objects declare Codeunit 400: Codeunit 412 "SMTP Test
Mail", Codeunit 9520 "Mail Management", Page 409 "SMTP Mail Setup" and Page 410 "SMTP User Specified
Address". All other mail senders go through Codeunit 9520, whose SMTP gate is `Codeunit 400.IsEnabled` – covered
by the patch above. `TESTFIELD("SMTP Server")` exists only in Codeunit 400 `CreateMessage`.

Things to check in **customer** databases (run [Find-SmtpCallers.ps1](../tools/Find-SmtpCallers.ps1)):

* objects that read `"SMTP Server"` directly to decide whether mail is possible (they would treat a Graph-only
  setup as "no mail") – change them to `SMTPMail.IsEnabled` (Codeunit 400);
* objects that call `GetSMTPMessage`;
* objects that use the `Microsoft.Dynamics.Nav.SMTP` DotNet type themselves (bypass Codeunit 400 entirely).

### From address with a fixed Graph Sender Mailbox

Codeunit 9520 `QualifyFromAddress` fills a blank From address from User Setup, the authentication e-mail,
Active Directory or the SMTP setup (*User ID*). In Graph mode with a fixed *Graph Sender Mailbox* the
From address is always the mailbox and the caller's address (if any, and different) becomes Reply-To; a blank
caller address is accepted by Codeunit 50400. Without a fixed mailbox the caller's From address must be a
mailbox the app may send as.

**Web client:** a blank From address does not always reach Codeunit 400/50400. When `QualifyFromAddress` finds
no address at all, it raises `FromAddressWasNotFoundErr` ("An email from address was not found. Contact an
administrator.") on the Web client before Codeunit 400 is called; the Windows client continues with a blank
From address. Codeunit 397 `GetBasicAuthAddressFromSMTPSetup` returns the SMTP *User ID* only when
*Authentication* = `Basic` and the User ID contains `@`, so a Graph-only setup with blank SMTP fields provides
no address. With a fixed *Graph Sender Mailbox*, therefore:

* give every user who sends mail from the Web client an e-mail address in **User Setup** (*E-Mail*) or in the
  User card (*Authentication Email*), or
* as a fallback, set SMTP **Authentication** = `Basic` and SMTP **User ID** = the *Graph Sender Mailbox* address.
  While *Mail Transport* = Microsoft Graph the SMTP fields are not used for sending, so this only feeds
  `QualifyFromAddress` (the resulting From address equals the mailbox, so no Reply-To is added). Enter a real SMTP
  password or reset these fields before switching *Mail Transport* back to SMTP.

This package does not patch Codeunit 9520 to skip the error.
